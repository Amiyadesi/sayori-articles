이전 글 [[astro-mizuki-blog-from-zero|Sayori Lite로 깔끔한 블로그 만들기]]에서는 GitHub, Cloudflare Pages와 선택 사항인 Obsidian 글쓰기 워크플로를 다뤘다

다 만들고 나면 기본 주소는 대충 이렇게 생겼다:

```text
https://你的项目名.pages.dev
```

쓸 수는 있지만 뭔가 살짝 아쉬운 느낌이다

블로그가 생겼으니 다음 단계는 자연스럽게 그럴듯한 도메인을 달아주고, 웹마스터 커뮤니티 몇 곳에 얼굴을 비추는 일이다. 당장 트래픽을 엄청나게 끌어모으려는 게 아니라, 이 웹사이트를 「내 컴퓨터 속 프로젝트 하나」에서 「인터넷상에 이름이 있는 작은 공간」으로 만들어 주는 과정이다

## 일단은 무료 도메인으로도 충분하다

당장 도메인을 구매하고 싶지 않다면 무료 2차 도메인으로 먼저 감을 익혀도 된다

요즘 내가 비교적 추천하는 곳은 DNSHE 같은 서비스다:

[https://my.dnshe.com/](https://my.dnshe.com/)

![[Pasted image 20260623151351.png]]

현재로선 Cloudflare에 연동할 수 있는 `cc.cd` 같은 최상위 도메인(접미사)을 우선적으로 보는 편이다

![[Pasted image 20260622231201.png]]

무료 도메인은 이런 용도로 쓰기 좋다:

- Cloudflare Pages 블로그에 커스텀 도메인 연결하기
- DNS 레코드 설정 연습하기
- Cloudflare 호스팅 익히기
- 나중에 쓸 셀프 호스팅 서비스용 서브도메인 미리 마련하기

반면 이런 용도로는 적합하지 않다:

- 장기 상업 프로젝트
- 중요한 이메일 주 도메인
- 절대 잃어버리면 안 되는 브랜드 메인 입구
- 정책 변경 리스크를 전혀 감당하고 싶지 않은 프로젝트

## DNSHE 지원 코드

DNSHE에는 서로 지원(부스트)을 주고받아 더 긴 기간의 2차 도메인을 얻을 수 있는 시스템이 있다

일단 지원 코드 몇 개를 여기에 올려두고, 나중에 새로 생기면 더 추가하겠다:

```text
VJC8UQYTPK
GHGMEUGWXA
VVN9QFPEUL
UUJ22RXYDC
G4HPCNW7R4
```

잠깐 블로그를 테스트해 보는 정도라면 굳이 영구 도메인에 집착할 필요 없다. 일단 DNS 설정이 되는 도메인을 하나 구해서 전체 흐름을 한 번 돌려보는 게 더 중요하다

## GitHub 학생 팩의 공식 무료 도메인

대학교 교육용 이메일이 있고 [GitHub Student Developer Pack](https://education.github.com/pack) 인증을 통과했다면, 공식으로 제공하는 첫해 무료 최상위 도메인 혜택 두 가지도 덤으로 챙길 수 있다:

- **Namecheap**: `.me` 최상위 도메인 1년 무료 등록 및 SSL 인증서 1년 제공
- **Name.com**: 지정된 최상위 도메인 중 첫해 무료 도메인 제공(선택 가능한 도메인 종류와 갱신 가격은 결제 페이지 기준)

주의할 점은 학생 팩의 최상위 도메인은 첫해만 무료이고 2년 차 갱신부터는 정상가로 돌아간다는 것이다. 카드 등록이나 갱신 신경 쓰기가 귀찮다면 그냥 위의 DNSHE를 계속 쓰는 편이 훨씬 마음 편하다

## Cloudflare에 연결하기

DNS, Pages, Tunnel의 구체적인 용도는 [[cloudflare-free-tier-developer-guide|Cloudflare 무료 플랜 튜토리얼]]에 정리해 두었으니, 여기서는 우선 도메인부터 연결해 보자

도메인을 구했다면 다음 단계는 Cloudflare 연결이다

가장 흔한 진행 순서는 다음과 같다:

1. Cloudflare에 사이트 추가하기
2. 안내에 따라 도메인의 네임서버(NS)를 Cloudflare로 변경하기
3. DNS 반영 기다리기
4. Cloudflare Pages 프로젝트에서 커스텀 도메인 추가하기
5. Pages에서 안내하는 대로 CNAME을 추가하거나 Cloudflare가 자동으로 설정하게 두기

무료 2차 도메인을 쓴다면 먼저 네임서버(NS) 변경을 지원하는지 확인해야 한다. NS 변경이 안 된다면 원래 도메인 플랫폼에서 직접 DNS 레코드를 추가하거나, Cloudflare 연동이 잘 되는 다른 도메인으로 갈아타는 게 낫다

여기서 조급해할 필요 없다. DNS 반영에는 시간이 좀 걸릴 때가 있다. 먼저 루트 도메인과 `www` / 서브도메인을 각각 어디로 연결할지 확실히 정해 두자. 이것저것 고치다 보면 방금 뭘 입력했는지도 헷갈리기 십상이다

## 셀프 호스팅 서비스용 서브도메인 비워두기

나중에 2C2G 학생용 서버 같은 걸 들이게 된다면 미리 서브도메인 구조를 짜 두는 게 좋다:

```text
vault.example.cc.cd  -> Vaultwarden
notes.example.cc.cd  -> Fast Note Sync
ntfy.example.cc.cd   -> ntfy
status.example.cc.cd -> Gatus
```

모든 서비스를 루트 도메인 아래에 다 우겨 넣지 말자

도메인은 집 주소 호수와 같다. 호수가 깔끔하게 나뉘어 있어야 나중에 서버를 옮기거나, 마이그레이션하거나, 리버스 프록시를 걸거나, 서비스를 내릴 때도 한결 수월하다

서버에서 돌릴 만한 서비스 총정리는 이 글을 참고하면 된다:

[[2c2g-server-service-index|2C2G 학생용 서버로 뭘 돌릴 수 있을까: 작은 서버 터지기 전에 알아둘 것]]

## 무료 도메인과 정식 도메인 선택 기준

나라면 이렇게 나눈다:

무료 도메인이 어울리는 경우:

- 막 블로그를 만들었을 때
- DNS를 공부할 때
- 튜토리얼 실습을 할 때
- Cloudflare Pages를 테스트할 때
- 셀프 호스팅 서비스를 시험 삼아 돌려볼 때

정식 도메인이 어울리는 경우:

- 오랫동안 꾸준히 운영할 블로그
- 정식 이메일 주소를 만들어야 할 때
- 프로필, 명함, 영상 소개란에 주소를 박아 넣어야 할 때

무료 도메인이 급이 떨어진다는 얘기가 아니다. 단지 장기 프로젝트에서 가장 골치 아픈 게 「나중에 이사하기 너무 번거로운 상황」이기 때문이다

이 블로그를 오래 쓰겠다고 마음을 굳혔다면 마음에 드는 도메인을 하나 사는 것도 충분히 가치가 있다. 개인 프로젝트에는 그 정도 사치쯤은 부려도 된다. 이름이 마음에 들어야 관리할 맛도 더 나는 법이다

# 웹마스터 커뮤니티 기웃거리기

도메인 세팅이 끝났다면 웹마스터 커뮤니티도 몇 군데 둘러보자

억지로 홍보하러 가는 게 아니라, 아직도 블로그를 쓰는 사람들이 모여 있는 분위기 속에 내 발을 들여놓기 위해서다. 독립 블로그는 혼자 쓰다 보면 금방 방구석 일기장이 되기 쉬운데, 가끔 다른 사람들은 어떻게 글을 쓰고 어떻게 꾸미고 서로 링크를 거는지 구경하다 보면 훨씬 동기부여가 된다

## 카이왕(开往) Travellings

카이왕은 블로그 링크 릴레이 프로젝트다:

[https://www.travellings.cn/](https://www.travellings.cn/)

방식이 꽤 귀엽다. 내 사이트에 「카이왕(开往)」 버튼을 달아 두면 방문자가 클릭했을 때 이 프로젝트에 참여한 다른 독립 사이트로 무작위 이동하게 된다

가입 안내:

[https://www.travellings.cn/docs/join.html](https://www.travellings.cn/docs/join.html)

어느 정도 글이 쌓인 블로그에 어울린다

막 개설해서 메인 화면이 텅 빈 상태로 신청하지 말자. 먼저 글 몇 편이라도 써 놓고, 누군가 클릭해서 들어왔을 때 실제로 볼거리가 있게 만들어 두는 게 좋다

## 멍베이(萌备)

멍베이는 멍국(萌国) ICP 등록이다:

[https://icp.gov.moe/](https://icp.gov.moe/)

신청 페이지:

[https://icp.gov.moe/join.php](https://icp.gov.moe/join.php)

공식 공신부 ICP 등록이 아니니 오해하지 말자. 서브컬처/개인 사이트 사이에서 일종의 재미 삼아 다는 배지이자 커뮤니티 입구에 가깝다

공식 신청 페이지에는 비상업적 사이트일 것, 회색 지대 콘텐츠가 아닐 것, 빈 껍데기 사이트가 아닐 것, HTTPS를 활성화할 것, 장기 접속이 가능할 것 같은 콘텐츠 조건이 걸려 있다

사이트 분위기와 잘 맞는다면 멍베이 번호를 하나 신청해서 푸터에 달아 보자. 실용적인 필수 요소는 아니지만 독립 사이트 특유의 감성이 살아난다

## 10년의 약속(十年之约)

10년의 약속:

[https://www.foreverblog.cn/](https://www.foreverblog.cn/)

핵심은 단순한 약속 하나다. 가입한 날부터 블로그를 10년 이상 닫지 않고 꾸준히 업데이트하며 활력을 유지하겠다는 다짐이다

조금 중2병스럽게 들릴 수도 있지만 나는 이런 감성이 꽤 마음에 든다

다만 운영 기간이 1년은 되어야 신청할 수 있으니 일단은 기다려 보자. 물론 이미 사이트를 1년 넘게 운영했다면 한 번쯤 신청해 보는 것도 좋겠다 ㅎㅎ

## 주찬(揪蝉)

주찬:

[https://hi.jiuchan.org/docs](https://hi.jiuchan.org/docs)

개인 웹사이트를 수집해 무작위 방문을 연결해 주는 플랫폼으로, 독립 사이트를 「랜덤 발견」 입구 안에 넣어 두는 느낌의 서비스다

블로그에 읽을 만한 글이 몇 편 쌓였다면 여기 등록 문서도 한번 살펴보자. 신생 사이트에 이런 플랫폼이 갖는 의미는 당장 엄청난 방문자 수를 꽂아주는 게 아니라, 사람들이 이 사이트 저 사이트 건너다니다 우연히 나를 발견할 기회를 만들어 주는 데 있다

## 중국어 독립 블로그 목록(中文独立博客列表)

GitHub: [https://github.com/timqian/chinese-independent-blogs](https://github.com/timqian/chinese-independent-blogs)

중국어 독립 블로그들을 모아 놓은 저장소다. 블로그 주소, RSS, 소개, 태그를 정리해 둔 장기 관리형 블로그 디렉터리에 가깝다

이런 사람에게 맞다:

- RSS를 지원한다

요즘은 사람들이 블로그를 직접 구독하기보다 플랫폼 알고리즘이 줄 세워 주는 정보만 받아먹는 경우가 많다. 중국어 독립 블로그 목록은 최소한 내가 좋아하는 사람을 직접 구독해서 보는 오래됐지만 좋은 방식을 지켜 주고 있다

내 사이트를 등록하려면 먼저 아래 항목들부터 채워 두자:

```text

站点 URL
RSS URL
一句话介绍
主题标签
```

[Cloudflare 연동 가능한 현재 오픈 무료 도메인 모음](https://www.nodeloc.com/t/topic/70964?u=amiya_desi)

nodeloc에 올라온 보물 같은 글인데, 꽤 많은 정보가 모여 있다

### GitHub Pages 기본 제공 도메인

당장 어떤 도메인 서비스도 만지고 싶지 않다면 GitHub Pages 자체에서 기본 주소를 하나 준다:

```text
你的用户名.github.io
```

Cloudflare Pages에서도 기본 주소를 준다:

```text
你的项目名.pages.dev
```

엄밀히 말해 둘 다 「온전한 내 도메인」은 아니지만, 글을 쓰고 프로젝트를 보여주기에는 충분하다. 나중에 마음이 정해졌을 때 정식 도메인을 사도 늦지 않는다

## 블로그에 댓글 시스템 달기

이전 글에서 댓글 시스템도 다루겠다고 했으니 여기서 마저 정리한다

블로그에 댓글창이 없어도 굴러가는 데는 지장 없지만, 튜토리얼이나 경험담, 삽질 기록을 쓰다 보면 가끔 「이 글 덕분에 해결했어요」라거나 「3단계에서 저는 좀 다른 문제가 떴어요」 같은 댓글이 달릴 때가 있다. 이런 소통이 오가면 서로 배울 점도 생기고, 이메일로 연락받는 것보다 훨씬 편하게 피드백을 주고받을 수 있다

내가 보기에 개인 정적 블로그에 잘 어울리는 댓글 시스템은 다음과 같다:

### Twikoo

[https://twikoo.js.org/](https://twikoo.js.org/)

GitHub: [https://github.com/twikoojs/twikoo](https://github.com/twikoojs/twikoo)

Twikoo는 중국어 독립 블로그 쪽에서 꽤 많이 쓰는 댓글 시스템이다. 익명 댓글, 이메일 알림, 이모티콘, 관리자 대시보드를 지원한다

배포 방식도 Vercel, Netlify, 클라우드 함수, 셀프 호스팅 Docker 등 다양하다. 학생 입장에서는 Vercel 무료 배포가 가장 손이 덜 가는 선택이다

장점:

- 중국어 생태계라 문서가 친절하다
- 배포 비용을 0원으로 맞출 수 있다
- 관리자 페이지에서 댓글 승인, 삭제, 답글이 가능하다
- 이메일 및 위챗 알림을 지원한다

단점:

- 데이터베이스 백엔드를 따로 골라야 한다(MongoDB Atlas 무료 플랜, Vercel KV, 혹은 직접 구축)
- 외부 무료 데이터베이스를 쓰면 데이터가 온전히 내 손안에 있지 않다

### Giscus

[https://giscus.app/](https://giscus.app/)

GitHub: [https://github.com/giscus/giscus](https://github.com/giscus/giscus)

Giscus는 GitHub Discussions를 댓글 백엔드로 활용한다. 방문자가 GitHub 계정으로 로그인해야 댓글을 남길 수 있다

장점:

- 데이터가 내 GitHub 저장소에 그대로 쌓인다
- 별도 서버 배포가 필요 없다
- 개발/기술 블로그라면 독자들도 대부분 GitHub 계정을 갖고 있다
- 마크다운 문법과 코드 하이라이팅을 기본 지원한다

단점:

- 무조건 GitHub 로그인이 필요하다
- 비개발자 독자는 댓글 하나 달자고 GitHub에 가입하려 하지 않을 수 있다
- 댓글이 저장소에 묶여 있어서 나중에 저장소를 옮기려면 마이그레이션이 필요하다

### Artalk

[https://artalk.js.org/](https://artalk.js.org/)

GitHub: [https://github.com/ArtalkJS/Artalk](https://github.com/ArtalkJS/Artalk)

Artalk는 백엔드 서비스를 직접 돌려야 하는 셀프 호스팅 댓글 시스템이다. 이미 2C2G 서버가 있다면 Docker로 띄워서 쓸 수 있다

장점:

- 데이터를 완전히 내가 통제할 수 있다
- 멀티 사이트 관리를 지원한다
- 이메일 알림, 텔레그램 알림, 캡차, 관리자 페이지 등 기능이 꽤 알차다

단점:

- 서버가 있어야 한다
- 관리하고 백업하고 업데이트해야 할 서비스가 하나 더 늘어난다
- 2C2G 서버에 서비스를 하나 더 얹는 셈이라 메모리 사용량을 신경 써야 한다

### 나라면 어떻게 고를까

막 블로그를 만들었고 서버가 없다면 Giscus나 Twikoo(Vercel 배포)부터 써 보는 걸 추천한다

이미 서버가 있고 독자층이 개발자만 있는 게 아니라면 Artalk를 고려해 볼 만하다

당장 댓글 기능까지 손대기 귀찮다면 안 달아도 전혀 문제없다. 먼저 글부터 잘 써 두고, 나중에 독자가 생겼을 때 추가해도 늦지 않는다. 블로그의 핵심은 댓글 시스템이 아니라 콘텐츠다

## 링크를 걸어 둘 만한 다른 곳들

- 우정 링크 페이지: 주제가 비슷한 블로거를 찾아 서로 링크 교환하기
- GitHub Profile: 개인 프로필 메인에 블로그 주소 걸어 두기
- Bilibili / YouTube / 샤오홍슈 소개란: 튜토리얼 영상에 글 링크 함께 달기
- Linux DO / V2EX 같은 포럼 서명: 커뮤니티 규칙을 지키면서 과하지 않게 달아 두기
- 오픈소스 프로젝트 README: 프로젝트와 관련된 블로그 글이 있다면 문서 링크로 연결하기

내 웹사이트로 들어오는 입구를 여러 군데 열어 두면 자연스럽게 찾아오는 사람도 늘어난다

## 블로그 통계: 누가 다녀갔는지 확인하기

도메인과 커뮤니티 입구까지 다 달고 나면 슬슬 이런 생각이 든다. 도대체 내 블로그를 보는 사람이 있긴 할까?

가볍게 쓸 수 있는 대안 몇 가지:

- **Umami**: [https://umami.is/](https://umami.is/), 셀프 호스팅도 가능하고 공식 무료 플랜도 쓸 수 있다. 인터페이스가 깔끔하고 데이터도 직접 관리할 수 있다
- **Cloudflare Web Analytics**: 이미 Cloudflare를 쓰고 있다면 기본 내장된 Web Analytics가 무료인 데다 별도 스크립트 삽입도 필요 없다. 대시보드에서 바로 확인하면 된다
- **Plausible**: [https://plausible.io/](https://plausible.io/), 유료 위주지만 직접 구축할 수도 있다
- **아무 분석 도구도 안 달기**: 이것도 괜찮다. 개인 블로그는 상업 사이트가 아니니 통계를 안 본다고 망하지 않는다

지금 내 추천은 일단 Cloudflare Web Analytics를 쓰는 것이다(어차피 이미 Cloudflare에 연결했을 가능성이 크니까). 그러다 나중에 부족하다 싶을 때 Umami를 고민해 보면 된다

매일 숫자만 들여다보지는 말자. 통계 보는 것보다 글 쓰는 게 훨씬 남는 장사다

## 마치며

막 만든 블로그는 처음부터 완벽하게 꾸미려고 애쓰지 말자

무료 도메인이 돌아가면 일단 그걸로 쓰고, Cloudflare 연결이 되면 그대로 굴려 보고, 커뮤니티는 하나씩 천천히 신청하고, 댓글 시스템은 나중에 달아도 늦지 않는다

진짜 중요한 건 계속 쓰는 것이다

도메인, 등록 번호, 우정 링크, 카이왕 버튼, 댓글창—이런 것들은 블로그를 좀 더 「웹사이트」처럼 보이게 해 주는 작은 장식일 뿐이다. 결국 블로그를 버티게 해 주는 힘은 글 그 자체다
