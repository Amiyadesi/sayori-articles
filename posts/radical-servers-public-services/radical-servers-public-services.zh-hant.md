我最近在 Riseup 的安全資源裏翻到一頁很長的名單

[激進服務器 - riseup.net](https://riseup.net/zh/security/resources/radical-servers)

名單裏的項目大多由非營利組織、自治技術團體、合作社或志願者集體維護，爲社會運動、草根組織、非商業項目和重視隱私的人提供網絡基礎設施

有些組織提供郵箱、郵件列表和網站託管，有些維護 VPN、XMPP、Matrix、Etherpad、文件分享、代碼託管或社區網絡

這頁名單讓我第一次比較完整地看到，互聯網角落中的其他公共服務

## Riseup 爲什麼把它們叫作激進服務器

Riseup 對這份名單的說明很直接

它收錄反資本主義、反等級、自治、女性主義或其他激進技術項目

其中一些團體爲草根行動者提供免費服務或互助服務，另一些更關注隱私、自由軟件和去中心化

共同點不是技術棧，而是不把賺錢當作第一目標

Riseup 也明確寫了，這份列表不等於官方背書

每個組織所在地區、法律環境、日誌政策、註冊方式和服務狀態都不同，使用前仍要自己閱讀條款與隱私說明

## 這份名單裏有什麼

頁面按 World Wide、South America、Europe、North America 和 In memoriam 分類

世界範圍的項目裏有 hackerspaces.org、HackThisSite、Indymedia 和 Take Back The Tech

它們分別偏向社區空間、網絡安全學習、獨立媒體和反對針對女性的數字暴力

南美部分列出 Codigosur 與 Colnodo

這些組織會爲社會運動和非營利團體提供託管、郵箱、郵件列表、流媒體、協作編輯與技術支持

歐洲部分數量最多

這裏能看到 Disroot、Framasoft、GreenNet、NoLog.cz、systemli、Syster Server、Koumbit 等不同方向的組織

它們提供的服務跨度很大

- 郵箱與郵件列表
- 網站、博客、Wiki 和論壇託管
- XMPP、Matrix、Mumble 和視頻會議
- Etherpad、CryptPad 與其他協作工具
- Git、項目管理與文件分享
- VPN、DNS、社區網絡和虛擬服務器
- 面向社會運動、女性主義團體或非商業項目的技術支持

北美部分包括 Riseup 自己，也收錄了 Koumbit 和 Anarchy Planet 等項目

頁面最後還保留一組 In memoriam

這些項目已經停止或只剩維護模式，卻沒有被簡單從歷史裏擦掉

這一段很重要，因爲公共服務會結束，維護者退出、資金變化和法律風險都可能讓一個曾經可靠的入口消失，這也就是公益所必須承擔的風險啊

## 幾個值得單獨認識的項目

### Disroot

[Disroot](https://disroot.org/) 是位於阿姆斯特丹的非營利基金會，由志願者維護並依賴社區支持

它把郵箱、文件、聊天、協作文檔、加密粘貼板和聯邦網絡工具放在一個開放服務集合裏

我之前單獨寫過 [[disroot-open-services-note|Disroot：一个很像互联网老理想的开源服务集合]]

### Framasoft

[Framasoft](https://framasoft.org/) 來自法國，長期推廣自由軟件、開放教育和去中心化互聯網

它做過大量替代中心化平臺的公共工具，也持續維護軟件、文檔和教育資源

### systemli 與 NoLog.cz

[systemli](https://www.systemli.org/) 爲政治活動者和社會運動提供注重隱私的通信服務

[NoLog.cz](https://nolog.cz/) 是捷克的活動者技術集體，提供 Matrix、文件分享、協作文檔、視頻和其他自由軟件服務

這類組織通常不會承諾面向所有人的無限資源，而會把支持對象、申請方式和使用邊界寫得很明確

### GreenNet 與 Koumbit

[GreenNet](https://www.greennet.org.uk/) 爲和平、環境和人權團體提供互聯網服務、網站與託管支持

[Koumbit](https://www.koumbit.org/) 是蒙特利爾的非營利組織，爲社區團體和社會正義項目提供自由軟件技術服務，也有團結託管計劃

它們提醒我，公益技術服務不一定全部免費

合理收費、交叉補貼、捐贈和志願勞動都可能是維持服務的方法

## 使用這份名單前要先確認三件事

我在 2026 年 7 月 19 日實際訪問了這份列表，目錄仍包含 World Wide、South America、Europe、North America 和 In memoriam

這隻能證明 Riseup 的目錄頁面當前可訪問，不能替名單裏的每一個組織證明服務仍然開放

第一，檢查項目現在是否仍在運行

這份頁面保留了歷史條目，部分服務說明和配額可能已經過時

第二，檢查誰適合申請

有些服務只面向特定地區、社會運動、非營利組織或受邀請用戶，不是看到免費就能註冊

第三，檢查法律與數據邊界

隱私友好不等於絕對匿名，也不等於可以忽略備份、賬號恢復和當地法律

重要資料仍要保留自己的加密備份，不把任何單一組織當成永遠不會關閉的基礎設施

## 我能從這份名單學到什麼

我沒有把 sayori.org 註冊成公益組織，也沒有這些團體的資金、成員和長期治理經驗

因此我不會把自己的小服務和 Riseup、Disroot 放在同一個規模上比較

我能學習的是它們如何說明服務對象、公開邊界、依賴捐贈、限制濫用，並承認服務可能停止

比起繼續堆很多入口，我更想保留少量真正能維護的服務

## sayori.org 目前開放的服務

完整狀態放在 [sayori.org 公共服務說明](https://sayori.org/zh/services/)

### GeoScore 網頁審計

[GeoScore](https://geo.sayori.org/) 是無需註冊的 SEO 與 GEO 事實審計工具

它面向公開網頁，整理站點畫像、抽樣頁面、檢查證據、優先修復項和 Markdown 報告

它不會自動修改目標網站，也不會把預測結果包裝成真實 AI 引用率

### GeoScore 公開審計 API

我目前還能提供一個公開 API 服務

入口是 [geo-api.sayori.org](https://geo-api.sayori.org/)

它提供 GeoScore 的穩定公開接口，可以運行公開域名審計、讀取部署元數據、獲取 PageSpeed 證據，並在已有審計上生成 Evidence Map 或 FixPack

API 的請求結構、響應和錯誤碼記錄在 [OpenAPI 文檔](https://geo-api.sayori.org/openapi.json) 中，中文使用說明在 [GeoScore Docs](https://geo.sayori.org/docs)

最小的站點審計請求如下

```bash
curl "https://geo-api.sayori.org/api/audit/example.com"
```

這個接口返回 Server-Sent Events 流，站點模式最多抽取五個 HTML 頁面

運行限制以 [`/api/meta`](https://geo-api.sayori.org/api/meta) 的線上結果爲準

它只接受公網 hostname，不支持 localhost、內網地址、IP literal 或任意代理請求

公開 API 也按盡力而爲原則運行，遇到額度耗盡、濫用或上游故障時會限流或暫停

### Amiya 的白板

[Amiya 的白板](https://board.sayori.org/) 是一個無需註冊的輕量瀏覽器白板

它適合臨時畫圖、整理草圖、講清楚一個頁面結構，或給別人發一張可以直接打開的協作紙面，臨時畫一些流程圖或者其他的展示自己思路的東西還是很好用的

白板仍按盡力而爲原則維護，不承諾長期保存重要內容，使用者應該自行導出需要保留的結果

### 博客、RSS 與反饋

[博客](https://blog.sayori.org/) 和 [RSS](https://blog.sayori.org/rss.xml) 用來公開文章、教程和項目記錄

留言板與郵件負責接收服務問題和改進建議

## Search Gateway 的邊界

[Search Gateway](https://github.com/Amiyadesi/search-gateway) 仍然開源，可以自行部署，也提供兼容 API 與 MCP 接入方式

但 `search.sayori.org` 是站長內部實例，需要鑑權，不提供匿名調用、共享 Token 或公共搜索額度

公開 GeoScore API 與內部 Search Gateway 必須分開說明

前者是可以調用的公共服務，後者是可自部署的軟件和私有基礎設施

## 下一步

對自己的站點，我會先把 GeoScore 網頁版、公開審計 API、博客和 RSS 維護穩定

如果以後增加網站體檢互助、靜態站上線協助或少量搜索證據額度，也會先邀請、限額和人工處理
