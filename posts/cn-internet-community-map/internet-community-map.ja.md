# 小規模フォーラム一覧リポジトリを作ってみた

以前からずっと、インターネットコミュニティの地図を作りたいと思っていた

ここで言うコミュニティとは、X、Instagram、貼吧、小紅書、小黒盒のような表立った大手プラットフォームではなく、自分から検索したり関連する界隈に首を突っ込んだりしない限り、まず自然に流れてこないようなフォーラムやコミュニティのことだ

これが今、1本の記事から長期的にメンテナンスできる独立リポジトリとオンラインページになった：

- GitHub リポジトリ：[https://github.com/Amiyadesi/small-forums-list](https://github.com/Amiyadesi/small-forums-list)
- オンラインページ：[https://forums.cc.cd/](https://forums.cc.cd/)

今のサイトは Wiki や docs に近い形になっている。左側にカテゴリとコミュニティ目次、中央に具体的な項目があり、各コミュニティに個別ページがあって、ページ下部には Giscus のコメント欄も繋いである

現在の初版には 49 個のコミュニティを収録した。今後誰かが補足や修正を入れたり PR を送ってくれたりすれば、この数字もまだまだ増えていくはずだ

## このリポジトリに何を収録するか

ここでの「小規模」は厳密なユーザー数ではなく、たどり着きやすさのルートで判断している

自分から検索しないとまず出会えない場所や、サーバー界隈、ACG 界隈、セキュリティ界隈、ハードウェア界隈、サイト運営界隈、リソース界隈などにいる人しか普段目にしないようなコミュニティなら、収録対象になり得る

現在はだいたいこんなカテゴリに分けている：

- 技術 / AI / 開発者
- ホスティング / VPS / サイト運営 / 個人サイト
- 検索 / リソース / ナレッジツール
- セキュリティ / リバースエンジニアリング / システム / ソフトウェア
- ACG / ゲーム / ニッチ界隈
- ハードウェア / 電子工作 / Homelab
- アダルト / リソース / グレーゾーン
- 海外の老舗フォーラム / 雑多・趣味全般

AI に分けさせたらちょっと妙な分類になった気もするけど、まあ仕方ないので一旦これでいく

## 今のページはどんな感じか

以前は長い README のリストみたいな状態だったが、今はサイトとして切り分けている。

トップページにはカテゴリ別の早見表を残していて、どんなコミュニティがあるかサッと眺めるのに向いている。左側の目次からはカテゴリごとにジャンプでき、各コミュニティの個別ページもあるので、記述の間違いや入り口の変更、登録ルールの変更などをピンポイントで指摘しやすくなった

最初は「インターネットコミュニティ地図」を作ろうとしていたけれど、書けば書くほど、地図作りで一番難しいのは描くことではなく維持し続けることだと気づいた

フォーラムの入り口は変わるし、登録方法も変わるし、コミュニティの空気感も変わる。サーバー界隈は業者や回線、キャンペーンのせいで新しい情報が次々出てくるし、ACG やリソース系のコミュニティもドメイン、権限、ローカルルールの変更でよく情報が古くなる

だから今は、リポジトリで目次と事実の記録をやり、ブログで個人の体験を書く、という方針にしている

自分が本当に長く入り浸ったコミュニティなら単独で記事を書くし、公開情報をまとめただけならリストに留めておく

## 各コミュニティについて何を書くか

リポジトリ内の各項目には、なるべく以下の情報を書くようにしている：

- 入り口
- 立ち位置とコミュニティの雰囲気
- 登録方法やハードル
- 中に主に何があるか
- 何を見るのに向いているか
- 注意事項
- 公開ソース
- 最終確認日

自分が長く入って体験したコミュニティは、もっとリアルな実感に近い書き方にしている。

たとえば Linux.do と NodeLoc については、以前自分が書いた[[internet-community-1|インターネットコミュニティ記録1]]での体験を参考に書いている。Linux.do のルール、初心者タスク、公益サイト、お得情報・バラマキ、開発チューニング、ドキュメント共同構築、LDC、それから NodeLoc の自由な雰囲気、サブフォーラム、バッテリーポイント、アフィリエイト、管理人のアクティブさなどだ

長く使ったことがないコミュニティについては、公開ページや界隈の評判をもとに整理するだけで、実体験のように装うことはしない

## なぜ PR を歓迎するのか

こういうリストは一人で作っていると絶対に間違いが出る

コミュニティによっては部外者には入り口しか見えず、中の本当の空気感がわからない。登録ルールが期間限定で開放されるフォーラムもあれば、ドメインが転々とする場所もあるし、旧称と新称がごっちゃになりやすいところもある

だからこのリポジトリに一番必要なのは、綺麗な紹介文ではなく、実際のメンバーによる修正だ

もしあるコミュニティの古参ユーザーだったり、単に項目の間違いに気づいたりしたら、気軽に PR を投げてほしい。特にありがたい補足はこんな感じの内容だ：

- 現在の登録は開放制、招待制、それとも期間限定開放か？
- 新規が入ったらまずどのローカルルールやお知らせを見るべきか？
- コミュニティの実際の雰囲気は技術寄り、雑談・荒れ寄り、売買寄り、それともリソース寄りか？
- 中で一番価値のある板はどこか？
- 入り口は変わっていないか、旧ドメインが不安定になっていないか？
- 一部の説明が AI の要約っぽすぎて、実際のユーザーの口調に直す必要がないか？

PR を出すのが面倒なら、該当するコミュニティページのすぐ下にコメントを残すのでもいい。サイトには今 Giscus を繋いでいるので、コメントは GitHub Discussions に保存される

## 整理に協力する方法

コミュニティを追加・修正するときは、まずリポジトリ内の構造化データを編集してほしい：

```bash
data/communities.json
```

編集が終わったら以下を実行する：

```bash
node scripts/generate-readme.mjs
node scripts/build-site.mjs
```

前者は README を同期し、後者はオンラインページを生成する

カテゴリの説明だけを直す場合はこちらを見ればいい：

```bash
docs/categories.md
```

個別のコミュニティを補足する場合は、できれば公開ソースも一緒に添えてほしい。ソースは公式サイト、登録ページ、サイト内のお知らせ、About ページ、ルールページ、その他公開アクセスできる説明なら何でもいい

## 現在の整理方針

このプロジェクトは今のところ、公開資料やサイトページ、それにわずかな個人体験をもとに AI が中心となって整理している。自分が本当に長く入り込んで体験したコミュニティはごく一部だけだ

だから今後は、各コミュニティが実際のユーザーの手によって少しずつ直されていくといいなと思っている

アダルト、リソース、クラック、リバースエンジニアリング、セキュリティ、ROM 焼き、売買といったコミュニティも収録するが、大枠ごとに「中にだいたい何があるか」「何の観察に向いているか」「どんな地雷があるか」を明確に書く。実際に足を踏み入れるか、参加するか、リスクをどう判断するかは、すべて読者の自己責任になる

今は、書いて終わりの古びていくブログ記事よりも、長く更新し続けられる公共のディレクトリとして育てたいと思っている

もし自分が書き漏らしているフォーラムを見つけたり、ある項目の記述が素人丸出しだったりしたら、ぜひリポジトリへ行って PR を出してほしい：

[https://github.com/Amiyadesi/small-forums-list](https://github.com/Amiyadesi/small-forums-list)
