# 작은 포럼 목록 저장소를 하나 만들었습니다

예전부터 인터넷 커뮤니티 지도를 한번 정리해보고 싶었습니다

여기서 말하는 건 X, 인스타그램, 티에바, 샤오홍슈, 샤오헤이허 같은 겉으로 드러난 대형 플랫폼이 아니라, 직접 검색하거나 관련 판에 발을 들이지 않으면 평소에 자연스럽게 접할 일이 거의 없는 포럼과 커뮤니티들입니다

이 작업은 이제 글 한 편에서 벗어나, 장기적으로 유지보수할 수 있는 독립 저장소와 온라인 페이지로 바뀌었습니다:

- GitHub 저장소: [https://github.com/Amiyadesi/small-forums-list](https://github.com/Amiyadesi/small-forums-list)
- 온라인 페이지: [https://forums.cc.cd/](https://forums.cc.cd/)

지금 이 사이트는 위키나 문서(docs)에 더 가까운 형태입니다. 왼쪽에는 분류와 커뮤니티 목차가 있고, 가운데에는 구체적인 항목이 나오며, 각 커뮤니티마다 개별 페이지가 있고 하단에는 Giscus 댓글창도 연결되어 있습니다

현재 첫 버전에는 49개의 커뮤니티가 수록되어 있습니다. 나중에 누군가 내용을 보충하거나, 오류를 수정하거나, PR을 보내주시면 이 숫자는 계속 바뀔 겁니다

## 이 저장소에는 무엇이 들어가나요

여기서 말하는 '작다'는 기준은 엄격하게 사용자 수로 따지는 게 아니라 접근 경로를 기준으로 합니다

직접 검색하지 않으면 거의 접할 수 없거나, 호스팅 판, ACG 판, 보안 판, 하드웨어 판, 웹마스터 판, 자료 공유 판 등에서 활동하는 사람들만 자주 보게 되는 커뮤니티라면 수록 대상이 될 수 있습니다

현재는 대략 이런 식으로 분류해 두었습니다:

- 기술 / AI / 개발자
- 호스팅 / VPS / 웹마스터 / 독립 사이트
- 검색 / 자료 / 지식 도구
- 보안 / 리버싱 / 시스템 / 소프트웨어
- ACG / 게임 / 소규모 마니아층
- 하드웨어 / 전자기기 / 홈랩(Homelab)
- 성인 / 자료 / 그레이존
- 해외 올드 포럼 / 범용 취미

AI가 나눈 거라 느낌이 좀 이상하긴 한데, 어쩔 수 없으니 일단은 이렇게 두려고 합니다

## 지금 페이지는 어떤 모습인가요

예전에는 긴 README 목록에 더 가까웠는데, 지금은 사이트 형태로 분리해 두었습니다.

메인 페이지에는 분류별 요약 보기를 남겨두어 어떤 커뮤니티들이 있는지 빠르게 훑어보기 좋고, 왼쪽 목차로는 분류별로 바로 이동할 수 있습니다. 각 커뮤니티마다 개별 페이지도 있어서, 누군가 특정 커뮤니티의 설명이 틀렸다거나, 접속 경로가 바뀌었다거나, 가입 규칙이 달라졌다고 바로 지적하기 편합니다

처음에 만들고 싶었던 건 '인터넷 커뮤니티 지도'였는데, 쓰면 쓸수록 지도는 그리는 것보다 꾸준히 유지보수하는 게 훨씬 어렵다는 걸 깨달았습니다

포럼 접속 주소도 바뀌고, 가입 방식도 바뀌고, 커뮤니티 분위기도 변합니다. 호스팅 판은 업체나 회선, 이벤트 때문에 계속 새 정보가 쏟아지고, ACG나 자료 커뮤니티도 도메인, 권한, 게시판 규칙이 바뀌면서 금방 옛날 정보가 되어버립니다

그래서 지금은 저장소가 목차와 사실 기록을 맡고, 블로그는 개인적인 경험을 쓰는 쪽으로 방향을 잡았습니다

제가 실제로 오래 활동해 본 커뮤니티라면 따로 글을 쓰고, 공개된 자료만 정리한 정도라면 목록에만 남겨두는 식입니다

## 각 커뮤니티 항목에는 무엇을 적나요

저장소의 각 항목에는 가급적 아래 정보들을 적으려 합니다:

- 접속 경로
- 정체성과 커뮤니티 분위기
- 가입 방식 또는 진입 장벽
- 내부에 주로 무엇이 있는지
- 어떤 내용을 보기에 적합한지
- 주의사항
- 공개 출처
- 마지막 확인 날짜

제가 오래 들어가서 직접 겪어본 커뮤니티는 실제 체감에 가깝게 적었습니다.

예를 들어 Linux.do와 NodeLoc은 예전에 썼던 [[internet-community-1|인터넷 커뮤니티 기록 1]]의 경험을 참고해서 적었습니다. Linux.do의 규칙, 뉴비 미션, 공익 사이트, 혜택/이벤트(福利羊毛), 개발 튜닝, 문서 공동 구축, LDC 같은 것들이나, NodeLoc의 자유로운 분위기, 하위 포럼, 배터리 포인트, AFF(제휴 마케팅), 웹마스터 활성도 같은 내용들입니다

오래 사용해 보지 않은 커뮤니티는 공개된 페이지와 해당 판에서 도는 이야기만 바탕으로 정리했고, 직접 겪어본 것처럼 꾸며내지 않았습니다

## 왜 PR을 환영하나요

이런 종류의 목록은 혼자서 정리하면 무조건 틀리는 부분이 생깁니다

어떤 커뮤니티는 외부인이 문앞까지만 볼 수 있고 실제 분위기는 볼 수 없습니다. 가입 규칙이 기간 한정으로만 열리는 포럼도 있고, 도메인이 계속 떠돌아다니는 곳도 있으며, 옛 이름과 새 이름이 헷갈리기 쉬운 곳도 있습니다

그래서 이 저장소에 가장 필요한 건 더 그럴듯한 소개글이 아니라, 해당 커뮤니티의 실제 멤버들이 해주는 수정입니다

특정 커뮤니티의 올드 유저이시거나, 그냥 어떤 항목이 잘못 적혀 있는 걸 발견하셨다면 바로 PR을 올려주셔도 됩니다. 보통 이런 보충 내용이 가장 값집니다:

- 현재 가입이 오픈 상태인지, 초대제인지, 아니면 기간 한정 오픈인지?
- 뉴비가 들어가면 어떤 게시판 규칙이나 공지부터 먼저 읽어야 하는지?
- 커뮤니티의 실제 분위기가 기술 위주인지, 잡담 위주인지, 거래 위주인지, 아니면 자료 공유 위주인지?
- 안에서 가장 가치 있는 게시판은 어디인지?
- 접속 경로가 바뀌었는지, 예전 도메인이 이미 불안정해졌는지?
- 일부 설명이 너무 AI 요약 티가 나서 실제 사용자 말투로 고쳐야 하는지?

PR을 올리기 번거로우시다면 해당 커뮤니티 페이지 아래에 바로 댓글을 남기셔도 됩니다. 사이트에 Giscus가 연결되어 있어서 댓글이 GitHub Discussions로 들어갑니다

## 정리를 돕는 방법

커뮤니티를 새로 추가하거나 수정할 때는 저장소 안의 구조화된 데이터를 우선 수정해 주세요:

```bash
data/communities.json
```

수정한 뒤에는 아래 명령어를 실행합니다:

```bash
node scripts/generate-readme.mjs
node scripts/build-site.mjs
```

앞의 것은 README를 동기화하고, 뒤의 것은 온라인 페이지를 생성합니다

분류 설명만 수정하려는 경우에는 아래 파일을 보시면 됩니다:

```bash
docs/categories.md
```

개별 커뮤니티를 보충할 때는 공개 출처도 함께 달아주시는 게 좋습니다. 출처는 공식 홈페이지, 가입 페이지, 사이트 내 공지, 소개(About) 페이지, 게시판 규칙 페이지, 또는 외부에서 공개적으로 접근 가능한 기타 안내문이면 됩니다

## 현재의 정리 원칙

이 프로젝트는 현재 AI가 공개 자료와 사이트 페이지, 그리고 약간의 개인 경험을 바탕으로 정리한 비중이 큽니다. 제가 실제로 오래 들어가서 경험해 본 커뮤니티는 일부에 불과합니다

그래서 앞으로는 각 커뮤니티가 실제 사용자들의 손을 거쳐 조금씩 다듬어지길 바라고 있습니다

성인, 자료, 크랙, 리버싱, 보안, 펌웨어 개조(刷机), 거래 관련 커뮤니티도 수록하기는 하지만, 큰 범주에 맞춰 안에 대략 무엇이 있고, 무엇을 둘러보기에 좋으며, 어떤 함정이 있는지를 명확히 적을 것입니다. 구체적으로 들어갈지 말지, 참여할지 말지, 위험을 어떻게 판단할지는 모두 독자 본인이 책임져야 합니다

저는 이걸 한 번 쓰고 나면 금방 구식이 되어버리는 블로그 글보다는, 오래도록 함께 고쳐 나갈 수 있는 공공 목차로 만들고 싶습니다

제가 미처 적지 못한 포럼을 발견하셨거나, 특정 항목이 너무 문외한처럼 적혀 있다고 느껴지신다면 저장소에 바로 PR을 올려주세요:

[https://github.com/Amiyadesi/small-forums-list](https://github.com/Amiyadesi/small-forums-list)

독립 블로그 관련 입구는 [[internet-community-3|웹마스터 커뮤니티와 조직]]에 따로 정리해 두었으니, 지도와 함께 천천히 둘러보시면 좋겠습니다
